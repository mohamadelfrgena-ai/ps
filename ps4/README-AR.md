# AddonStation PS4 Preview — تطبيق تجريبي مستقل

هذا مجلد مستقل لتجربة عميل PS4 بلغة **C++17**. لا يغيّر تطبيق Android ولا ينسخ قاعدة البيانات: يقرأ العميلان من **مشروع Supabase نفسه** عبر HTTPS/REST.

## ما يفعله الإصدار التجريبي

- شاشة تلفاز بدقة 1920×1080 تعمل بـ SDL2 وتُدار بيد DualShock 4.
- يعرض أحدث 12 محتوى منشوراً من `public.content_items` والخطط المفعّلة من `public.subscription_plans` عند ضبط Supabase.
- عند عدم ضبط Supabase أو تعذّر الاتصال، يعرض تلقائياً **6 عناصر و3 خطط وهمية محلية** للاختبار، مع شارة `DEMO DATA ONLY`؛ لا تُرسل هذه البيانات إلى الخادم.
- يجلب البيانات الحقيقية للقراءة فقط؛ لا يسجّل دخولاً، ولا ينشئ مدفوعات، ولا يعدّل قاعدة البيانات، ولا ينزّل ملفات المحتوى.
- يستخدم المفتاح العام فقط في ترويسة `apikey`، مع تحقق TLS الافتراضي. لا يعطّل التحقق من الشهادة.
- يعرض رسالة واضحة إذا لم يُضبط الرابط/المفتاح أو منعت RLS/GRANT القراءة.

يمكن لاحقاً أن يستخدم عميل iOS وبرنامج PC **الرابط والمفتاح العام نفسيهما**، مع واجهة مستقلة لكل منصة. كل عميل يتصل بالخادم؛ لا توجد قاعدة بيانات منفصلة في PS4.

## الإعداد

### 1) إعداد OpenOrbis

يلزم حاسوب Linux أو macOS عليه OpenOrbis PS4 Toolchain وأدوات `clang`, `clang++`, `ld.lld` وأدوات إنشاء PKG. يلزم أيضاً توفر مكتبة SDL2 الخاصة بالـ PS4 ضمن الـ toolchain.

```bash
export OO_PS4_TOOLCHAIN="/المسار/إلى/OpenOrbis-PS4-Toolchain"
```

### 2) وضع القائمة الوهمية فقط (لا يحتاج قاعدة بيانات)

إذا أردت تجربة الواجهة ببيانات وهمية فقط، **لا تنشئ** `ps4/config.local.hpp` ولا تضع أي مفتاح. عند التشغيل يعرض التطبيق 6 عناصر و3 خطط وهمية، ولا يرسل طلبات إلى Supabase.

### 3) إعداد مشروع Supabase المشترك (اختياري للبيانات الحقيقية)

```bash
cp ps4/config.local.example.hpp ps4/config.local.hpp
```

عدّل `ps4/config.local.hpp` وضع **Project URL** و**Publishable key** نفسيهما المستخدمين في Android:

```cpp
inline constexpr char kSupabaseProjectUrl[] = "https://YOUR-PROJECT.supabase.co";
inline constexpr char kSupabasePublishableKey[] = "sb_publishable_...";
```

`config.local.hpp` مستثنى من Git عمداً. إذا لم تنشئه، فالتطبيق يعمل بوضع البيانات الوهمية المحلي ولا يرسل طلبات Supabase. لا تضع فيه `sb_secret_...` أو `service_role`؛ الكود يرفضهما. تُقبل مفاتيح Supabase الجديدة `sb_publishable_...`، أو مفاتيح `anon` القديمة فقط إذا كان ادعاء JWT يحتوي `role=anon`.

### 4) الاختبارات والبناء

```bash
make -C ps4 host-test   # اختبار محلل JSON وطبقة Supabase على الحاسوب
make -C ps4             # بناء SELF وتجهيز ملف PKG عبر OpenOrbis
```

اسم الحزمة الناتجة:

```text
IV0000-ASTN00001_00-ADDONSTATION0000.pkg
```

إذا كان مشروعك يستخدم إصداراً مختلفاً من OpenOrbis، راجع مكتبات SDL2 وأسماء أدوات `PkgTool.Core`, `create-gp4`, `create-fself` في `ps4/Makefile`.

## التحكم

| يد التحكم | لوحة المفاتيح عند الاختبار |
|---|---|
| D-pad أعلى/أسفل | ↑ / ↓ — اختيار محتوى أو خطة |
| L1 / R1 أو D-pad يسار/يمين | ← / → — التبديل بين المحتوى والخطط |
| △ أو Options | R / Enter — تحديث البيانات |
| ○ | Esc — الخروج |

## قاعدة البيانات والصلاحيات

الاستعلامات للقراءة فقط:

- `content_items`: `is_published = true`، أحدث 12 صفاً.
- `subscription_plans`: `active = true` مرتّبة حسب `sort_order`.

يعتمد الاختبار على صلاحيات القراءة العامة الموجودة في `supabase/04_rls.sql` و`supabase/11_grants.sql`. إن ظهرت `HTTP 401/403` فتحقق من المفتاح العام ومن أن سياسات RLS والمنح نُفّذت على **المشروع نفسه**.

## حدود النسخة الحالية

- هذه واجهة عرض أولية باللغة الإنجليزية وبخط نقطي مدمج؛ أي عنوان عربي/Unicode يظهر كعلامات `?` في هذه النسخة. دعم العربية وRTL يحتاج محرك تشكيل/عرض مناسباً على PS4.
- لا توجد مصادقة أو محفظة AC أو دردشة أو شراء أو تنزيل ملفات بعد. العمليات الحساسة تبقى في تطبيق Android الحالي إلى أن نضيف تدفق مصادقة آمناً لهذه المنصة.
- ملف PKG الناتج من OpenOrbis حزمة homebrew تجريبية، وليس حزمة متجر PlayStation رسمية. يستهدف بيئة PS4 متوافقة مع homebrew مثل GoldHEN، لكن التوافق الفعلي يعتمد على إصدار النظام وGoldHEN؛ لم يُتحقق من التشغيل على جهاز فعلي. يضم البناء وحدات التشغيل وملف `right.sprx` من عينة SDL2 المرفقة مع OpenOrbis.
- المستودع الحالي يحتوي تطبيق Android وقاعدة Supabase فقط؛ لا توجد فيه بعد تطبيقات iOS أو PC، لكن المخطط يسمح لها باستخدام مشروع Supabase نفسه.

│   ├── orbis_http_transport.*   # HTTPS عبر SceNet/SceSsl/SceHttp
