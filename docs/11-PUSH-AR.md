## ٠) كيف تعمل المنظومة (صورة سريعة)

```
                     Supabase (لا شيء سري داخل التطبيق)
  رسالة شات ─┐
  محتوى جديد ─┼─► زناد في القاعدة يكتب صفاً في push_queue
  صديق جديد  ─┘        │
                       ├─ يقرأ إعدادات المستخدم (master + قسم + ساعات هدوء)
                       ├─ يجمع الرسائل المتكرّرة (collapse_key) بدل إغراقك
                       └─ يؤجّل غير العاجل خارج ساعات هدوء *بتوقيت المستخدم*
                       ▼
        دالة send-push (Supabase Edge Function) كل يوم + عند الطلب
                       │  تقرأ الخانة، تُترجم النص إلى لغة كل جهاز،
                       │  وتُرسل عبر FCM v1 بمفتاح الخدمة (سرّي)
                       ▼
                 Firebase Cloud Messaging (FCM)
                       ▼
        الهاتف: PushService يستقبل رسالة «بيانات فقط» ويرسمها
                بنفسه بلغة الجهاز وعلى القناة الصحيحة
```

**لماذا «بيانات فقط» (data-only)؟** لأن نصّ الإشعار يُجهَّز على الهاتف بلغة
المستخدم، ولكل قسم قناة أندرويد مستقلة (Chat/Content/Social/Account/Reminders)
⇒ يستطيع المستخدمون كتم قسم واحد من إعدادات النظام وحدها دون تعطيل البقية.

**الصور داخل الإشعار:**
- إضافة/عالم جديد ⇒ **صورة الغلاف كبيرة** داخل الإشعار (BigPicture) — يراها
  المستخدم قبل أن يفتح التطبيق.
- رسالة شات أو طلب صداقة ⇒ **صورة المرسل دائرية** بجانب النص.
- لو تأخّر تنزيل الصورة (شبكة ضعيفة) يظهر الإشعار نصّاً عادياً في ثوانٍ —
  لا يُفقد الإشعار أبداً بسبب صورة.

**الأقسام الخمسة:**

| القسم | ماذا يشمل | ملاحظات |
|-------|-----------|---------|
| `chat` | رسائل الغرف · الإشارات (@) · الردود | صوت + إشعار مرتفع، وتجميع ذكي |
| `content` | إضافة/عالم/خريطة جديدة | **ملخّص واحد يومياً كحد أقصى** |
| `social` | طلبات الصداقة والتفاعل الاجتماعي | |
| `account` | تفعيل الاشتراك · الدفع · AC | **بلا صوت** |
| `reminders` | تذكير العودة | بلا صوت · مرة كل أسبوعين كحد أقصى |

**ساعات الهدوء (افتراضي ٢٣:٠٠ → ٠٨:٠٠):** تُحسب بتوقيت المستخدم نفسه
(`tz_offset` المُرسَل من الجهاز)، وغير العاجل ينتظر انتهاءها. أما الإشارات
والردود فتصله فوراً (تأخيرها يُلغي معناها).

### عرض الاشتراك للخطة المجانية («أفضل وأجدد الإضافات والعوالم»)

مَن هو على **الخطة المجانية** (أو انتهى اشتراكه) تصله رسالة واحدة كل **٣٠ يوماً**
تقول: «أفضل وأجدد الإضافات والعوالم — اشترك لتفتح كل الإضافات والعوالم
الحصرية، وتصلك الجديدات أولاً»، وتفتح **شاشة الخطط** مباشرة عند الضغط.

وبقواعد صارمة تمنع أن تصير إزعاجاً:

| القاعدة | القيمة |
|---------|--------|
| تكرار العرض | مرة واحدة كل **٣٠ يوماً** لكل مستخدم |
| عمر الحساب | ٧ أيام على الأقل (لا نُربك المستخدم الجديد) |
| النشاط | فعّال خلال ٢١ يوماً — أما الغائب فله **تذكير عودة** لا عرض بيع |
| صمت أسبوع | لا يُرسل لمن وصله أي إشعار آخر خلال ٧ أيام (لا نبيع لمن نزعجه) |
| المفتاحان | يخضع للمفتاح الرئيسي + مفتاح قسم «محتوى جديد» + ساعات الهدوء |
| المشتركون | لا تصله، ومن انتهى اشتراكه تصله (عاد مجانياً) |

> القاعدة الزمنية محفوظة في عمود دائم (`push_prefs.last_offer_at`) لا في سجل
> الطابور — لأن سجل الطابور يُنظَّف بعد ٧ أيام. الأمر نفسه ينطبق على تذكير
> الغياب (`last_reengage_at`) فقاعدة «مرة كل أسبوعين» مضمونة دائماً.

## ١) إنشاء مشروع Firebase (٥ دقائق)

1. افتح <https://console.firebase.google.com> → **Add project**.
2. الاسم: `AddonStation` (أي اسم) → أوقف Google Analytics (غير لازم) → **Create**.
3. من الشاشة الرئيسية: **Add app** → اختر أيقونة **Android**.
4. **Android package name:** `com.addonstation.mobile`
   — ⚠️ يجب أن يكون مطابقاً حرفياً، وإلا لن يصل أي إشعار.
5. اسم مختصر (App nickname): `AddonStation Android` ثم **Register app**.
6. نزّل الملف **`google-services.json`**.

### ١.١ وضع الملف في المشروع

```text
android/app/google-services.json      ← ضعه هنا (نفس مجلد build.gradle.kts)
```

هذا كل شيء. ملف `build.gradle.kts` مُعدّ مسبقاً بحيث:
- **إن كان الملف موجوداً** ⇒ يُفعَّل مكوّن `google-services` وFirebase Messaging تلقائياً.
- **إن لم يكن موجوداً** ⇒ التطبيق يُبنى عادةً بلا أي خطأ (الإشعارات تكون
  معطّلة، وتظهر في الشاشة لافتة «غير مُهيّأة»).

> 📱 **من الجوال بلا تحرير ملفات:** ضع نصّ الملف في سرّ باسم
> `ADDONSTATION_GOOGLE_SERVICES_JSON` (Settings → Secrets and variables →
> Actions) ⇒ سير البناء يكتبه في `android/app/` تلقائياً. أو أرسل الملف
> للمساعد في المحادثة ليضعه في المودع (الملف ليس سرّاً).
>
> 🔒 **لا تضع أي مفتاح خدمة داخل التطبيق.** ملف `google-services.json`
> ليس سرّاً (هو مُعرّف هوية فقط)، أما مفتاح الإرسال فيبقى في Supabase وحده.

## ٢) إنشاء مفتاح الخدمة السرّي (Service Account) — ٥ دقائق

1. Firebase Console → ⚙️ **Project settings** → تبويب **Service accounts**.
2. اضغط **Generate new private key** → **Generate key** ⇒ ينزل ملف JSON
   (اسمه مثل `addonstation-xxxx-firebase-adminsdk-xxxx.json`).
3. **لا تشارك هذا الملف ولا تضعه في Git** — إنه يسمح بالإرسال باسم مشروعك.

## ٣) رفع الأسرار إلى Supabase (٥ دقائق)

من <https://supabase.com/dashboard> → مشروعك → **Project Settings → Edge Functions
→ Secrets** (أو عبر CLI):

| الاسم | القيمة | لماذا |
|-------|--------|-------|
| `FCM_SERVICE_ACCOUNT` | **محتوى** ملف JSON كاملاً (انسخ كل النص) | يرسل باسمك |
| `PUSH_CRON_SECRET` | كلمة سرّية طويلة تخترعها (٣٢ حرفاً+) | حماية من استدعاء غريب |

عبر CLI (لو تفضّل الطرفية):

```bash
supabase secrets set PUSH_CRON_SECRET="اكتب-هنا-سرّاً-طويلاً-عشوائياً"
supabase secrets set FCM_SERVICE_ACCOUNT="$(cat ~/Downloads/addonstation-xxxx.json)"
```

> `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` يضعهما Supabase تلقائياً لكل
> دالة Edge — لا حاجة لنسخهما.

## ٤) نشر الدالة (دقيقتان)

من جذر المشروع:

```bash
supabase functions deploy send-push --no-verify-jwt
```

`--no-verify-jwt` مقصود: النداء يأتي من مجدول Cron وليس من مستخدم مسجّل،
والحماية تأتي من ترويسة `x-push-secret` بدلاً من ذلك.

### ٤.١ جرّبها يدوياً

```bash
curl -sS -X POST "https://<PROJECT-REF>.supabase.co/functions/v1/send-push" \
  -H "x-push-secret: <PUSH_CRON_SECRET>" \
  -H "content-type: application/json" \
  -d '{"action":"all"}'
```

المتوقّع: `{"ok":true, ...}` مع عدّاد `sent`/`skipped`. تعيد نفس الاستدعاء؟ آمن —
لا تُرسل الرسالة مرتين.

| القيمة (`action`) | ماذا تفعل |
|-------------------|-----------|
| `dispatch` | ترسل كل ما حان وقته في الطابور (الاستعمال اليومي) |
| `reengage` | تفحص الغائبين وتُرسل التذكير وفق القواعد |
| `offer` | عرض اشتراك للمجانيين وفق القواعد (مرة/٣٠ يوماً) |
| `cleanup` | تحذف أجهزة ميتة (١٨٠ يوماً) وصفوف قديمة (٧ أيام) |
| `all` | الثلاثة معاً (**الوضع الموصى به للـ Cron**) |

## ٥) الجدولة اليومية (٣ دقائق)

الخيار الأول — **Cron داخل Supabase** (SQL Editor، نفّذه مرة):

```sql
select cron.schedule(
  'as-push-daily',          -- الاسم
  '0 9 * * *',              -- ٩:٠٠ صباحاً UTC = ١١:٠٠ بتوقيت ليبيا
  $$
  select net.http_post(
    url     := 'https://<PROJECT-REF>.supabase.co/functions/v1/send-push',
    headers := jsonb_build_object(
                 'content-type',  'application/json',
                 'x-push-secret', '<PUSH_CRON_SECRET>'),
    body    := '{"action":"all"}'::jsonb
  );
  $$
);
```

> يحتاج تفعيل الامتدادين `pg_cron` و`pg_net` من **Database → Extensions** أولاً.

الخيار الثاني — **Cron خارجي مجاني**: أنشئ مهمة على <https://cron-job.org>
تستدعي العنوان نفسه بـ POST كل يوم والترويسة `x-push-secret` نفسها.

الخيار الثالث — **عند كل رسالة شات فوراً** (اختياري، يرفع السرعة):
أضف Webhook في Supabase (Database → Webhooks) على جدول `push_queue`
أو على `chat_messages` ينداء الدالة بـ `{"action":"dispatch"}`.

## ٦) الفحص من التطبيق (٣ دقائق)

1. افتح التطبيق وأنت **مسجّل الدخول** ⇒ يسجّل الجهاز تلقائياً (وتظهر الموافقة
   على أندرويد ١٣+).
2. ⚙️ الإعدادات → **الإشعارات** → الشاشة الجديدة:
   - المفتاح الرئيسي + ٥ أقسام مستقلة.
   - ساعات الهدوء: من/إلى مع أزرار − / +.
   - «تذكير العودة»: ٧ / ١٤ / ٣٠ يوماً.
   - زر **«أرسل لي إشعاراً تجريبياً»** ⇒ يجب أن يصل خلال ثوانٍ (يتجاوز ساعات
     الهدوء عمداً، حتى تتأكد أن كل شيء يعمل).
3. أرسل رسالة شات من حساب آخر ⇒ يصل الإشعار **بصورة المُرسِل** بجانبه.
3.١ انشر إضافة/عالماً جديداً من لوحة الإدارة (مع صورة غلاف) ⇒ يصل الإشعار
   **بصورة الإضافة كبيرة** — هذه أوضح صورة يراها المستخدم قبل الفتح.
4. أطفئ **قسم الشات** وحده ثم أرسل رسالة أخرى ⇒ لا يصل شيء، وبقية الأقسام تعمل.
4.١ لتجربة **عرض الاشتراك** فوراً: `curl` بالأمر `{"action":"offer"}` — يصل
   لحسابك إن كان مجانياً، فعّالاً، ومضى على إنشائه ٧ أيام، ولم يصله إشعار
   خلال أسبوع (وإلا فالسلوك صحيح: القاعدة تحميك من الإزعاج).
5. أغلق التطبيق تماماً (من قائمة التطبيقات الأخيرة) وكرّر ⇒ يصل الإشعار أيضاً
   (هذا ما يجعل الإشعار «حقيقياً»: الخادم هو المُرسِل، لا التطبيق).

### استكشاف الأخطاء

| الحالة | السبب المرجّح | الحل |
|--------|----------------|------|
| «هذا الجهاز غير مسجّل بعد» | لم يُنفَّذ `34_push_notifications.sql` أو لم تُفتح الجلسة | نفّذ 34 ثم افتح التطبيق مسجّلاً |
| الشاشة تقول «غير مُهيّأة» | `google-services.json` غير موجود في `android/app/` | أضِفه وأعد بناء التطبيق |
| الدالة ترجع `unauthorized` | `PUSH_CRON_SECRET` مختلف في الجانبين | وحّد القيمة |
| `sent: 0` دائماً | مفتاح الخدمة ناقص/تالف | أعد رفع `FCM_SERVICE_ACCOUNT` |
| تصل بلا صوت | المستخدم كتم القناة، أو القسم من نوع account/reminders | طبيعي (مقصود) |
| الإشعار بلا صورة | غلاف الإضافة غير مرفوع، أو تنزيل الصورة تأخّر | أضف غلافاً للإضافة (مخزن `site-assets`) — والنص يصل دائماً |
| لا يصل على iPhone | المشروع أندرويد فقط حالياً | إن أردت iOS: أضف تطبيق iOS في Firebase ثم يتبع نفس الإعداد |

## ٧) قواعد «عدم الإزعاج» المدمجة (لا تحتاج أي إعداد)

- **تجميع**: ١٢ رسالة في غرفة واحدة ليست ١٢ إشعاراً — إشعار واحد يُحدَّث
  (collapse)، ورسائل الغرفة الواحدة لا تكرّر أكثر من مرة كل ٥ دقائق.
- **ملخّص المحتوى**: الإضافات/العوالم = إشعار تجميعي واحد يومياً كحد أقصى.
- **ساعات هدوء**: تُحسب بتوقيت المستخدم، وغير العاجل ينتظر الفجر ليمر بأمان.
- **تذكير الغياب**: بعد الغياب (افتراضي ٧ أيام)، لحساب عمره ٣ أيام على الأقل،
  ومرة واحدة كل أسبوعين كحد أقصى. لا ملاحقة.
- **مفتاح رئيسي**: إطفاؤه يُسكِت كل شيء فوراً بلا فقدان الحساب.
- **تنظيف ذاتي**: الأجهزة المهجورة والصفوف القديمة تُحذف تلقائياً.
