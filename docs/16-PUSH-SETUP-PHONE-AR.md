# ١٦ — دليل الإشعارات الحقيقية **من الجوال** خطوة بخطوة

> **لمن هذا الملف؟** لك أنت. كل خطوة مكتوبة كما ستراها على شاشتك بالحرف،
> وبأقل ما يمكن من الكتابة على الجوال.
>
> **الزمن:** ١٥–٢٠ دقيقة، مرة واحدة في العمر.
> **التكلفة:** صفر (الطبقة المجانية تكفي بمراحل).
>
> كل ما يخصّ الخادم **جاهز ومكتوب**؛ الذي بقي هو مفتاح مشروعك في Firebase
> (لا يُنشئه إلا حسابك في Google) ثم بناء نسخة تطبيق تحمله.

---

## سؤال: لماذا أحتاج Firebase أصلاً؟

**الجواب المختصر:** لأنك لا تستطيع أن تُوقظ جوال المستخدم بنفسك. أندرويد يمنع
التطبيقات من إبقاء اتصال دائم بالسيرفر (وإلا نزفت البطارية)، ويوفّر بدلاً منه
**قناة نظام واحدة مشتركة** يديرها Google Play Services — وFirebase Cloud
Messaging (FCM) هو الباب الرسمي الوحيد للوصول إليها. بلا هذا الباب، لا تصل
الرسالة إلا والتطبيق مفتوح.

**الوقائع الأربع التي تُغلق الموضوع:**

| الحقيقة | الأثر |
|---|---|
| أندرويد يمنع اتصالاً خلفياً دائماً (Doze + قيود الخلفية + سياسة Google Play) | «اتصال خاص بالتطبيق» يحتاج خدمة أمامية وإشعاراً دائماً في شريط الحالة + استهلاك بطارية + احتمال أن يقتله النظام |
| FCM مجاني بلا حدود: لا سعر لكل رسالة ولا سقف شهري ولا بطاقة ائتمان | التكلفة صفر حتى مع ملايين الإشعارات |
| كل خدمات الإشعارات الأخرى في أندرويد تمرّ عبر FCM تحت الغطاء (OneSignal وغيرها) | «بديل» مثل OneSignal = طبقة إضافية فوق FCM، لا استغناء عنه |
| البديل الحقيقي الوحيد هو اتصال خاص (مثل Pushy أو WebSocket من عندنا) | تعقيد صيانة + بطارية + سقوط إشعارات عند قتل النظام للتطبيق + كلفة |

**وما نأخذه من Firebase فعلاً؟** مشروع مجاني + ملف واحد صغير
(`google-services.json`) يُدمج في التطبيق ليعرف «إلى أي قناة يسمع». نحن **لا**
نستعمل قواعدهم ولا تخزينهم ولا تحليلاتهم (أوقفناها). الإرسال يتم من سوبابيز
بمفتاح خدمة يُصادق عند Google فقط. Google تُمرّر في قناتها نصّ الإشعار ومعرّف
الجهاز — ولا شيء من بيانات تطبيقك (لا الحسابات ولا الرسائل المخزّنة ولا الملفات).

**وإن كانت جوالات جمهورك بلا خدمات Google (نادر جداً في ليبيا والخليج):** هناك
بديل ثالث (Pushy) لا يعتمد على Google لكنه خدمة خارجية بتكلفتها وقيودها.

## ✅ حالة التنفيذ الفعلية (مُوثَّقة من التشغيلات الحقيقية)

نُفِّذ كل شيء على الخادم آلياً وتحقّقنا منه بنتائج فعلية (سير «Push doctor»):

| البند | الحالة | الدليل من التشغيل |
|---|---|---|
| المشروع يستجيب | ✓ | HTTP 200 |
| `35_push_live.sql` مُنفَّذ | ✓ | دالة `push_doctor` موجودة |
| `pg_cron` (الجدولة) | ✓ | الإضافة مفعّلة |
| `pg_net` (النداء للخارج) | ✓ | الإضافة مفعّلة |
| مهمّتا الجدولة (كل دقيقة + يومية) | ✓ | مسجّلتان |
| رابط دالة الإرسال + سرّ التشغيل في القاعدة | ✓ | محفوظان |
| دالة `send-push` منشورة | ✓ | منشورة من المودع |
| أسرار الدالة (`FCM_SERVICE_ACCOUNT` + `PUSH_CRON_SECRET`) | ✓ | مُزامَنة عبر واجهة الإدارة |
| **نداء حيّ للدالة** | ✓ | **ردّت 200** (السلسلة كاملة تعمل) |
| **ملف Firebase في الأسرار** | ✓ | `project_id = addonstation-6586d` · **حزمة التطبيق مطابقة** |
| أجهزة مسجّلة | ⏳ | 0 — يلزم تثبيت نسخة تحمل Firebase |
| نسخة التطبيق المسجّلة | ⏳ | بُنيت بلا `google-services.json` |
| الطابور يتحرّك | ⏳ | لا شيء لجهاز بعد (طبيعي) |

**معنى ذلك:** لا شيء ناقص في الخادم. الباقي **خطوة واحدة**: بناء نسخة جديدة
تحمل `google-services.json` (يُدمج فيه آلياً من الأسرار)، ثم تثبيتها.

> ملاحظة عن سرّ التشغيل: يُولَّد تلقائياً ويُزامَن على القاعدة والدالة في كل
> تشغيل ⇒ لا حاجة لحفظه. وإن أردت ثباته أضف `ADDONSTATION_PUSH_CRON_SECRET`
> كسرّ في المودع (تجده مطبوعاً في ملخّص أي تشغيل).

## المرحلة أ — إنشاء مشروع Firebase (من متصفح الجوال · ٥ دقائق)

1. افتح <https://console.firebase.google.com> وسجّل الدخول بحساب Google.
2. اضغط **Create a project** (إنشاء مشروع).
3. الاسم: `AddonStation` → **Continue**.
4. أوقف **Enable Google Analytics** (غير لازم) → **Create project** → انتظر ثوانٍ → **Continue**.
5. في صفحة المشروع اضغط أيقونة **Android** (أو ⚙️ *Project settings* → *General*
   → انزل إلى **Your apps** → **Add app** → أيقونة Android).
6. **Android package name** — انسخ هذا النصّ **حرفياً** بلا أي تغيير:

   ```
   com.addonstation.mobile
   ```

   ⚠️ لو اختلف حرف واحد لن يصل أي إشعار أبداً.
7. **App nickname**: `AddonStation Android` (أي اسم) → **Register app**.
8. اضغط **Download google-services.json** — ينزل ملف صغير على جوالك.
9. **Next → Next → Continue to console**. (لا نبني شيئاً الآن — الملف كافٍ.)

## المرحلة ب — مفتاح الخدمة السرّي (٣ دقائق)

1. ⚙️ **Project settings** → تبويب **Service accounts**.
2. زر **Generate new private key** → **Generate key**
   ⇒ ينزل ملف ثانٍ اسمه مثل `addonstation-xxxx-firebase-adminsdk-xxxx.json`.
3. 🔒 **هذا الملف سرّ حقيقي** (يملك الإرسال باسم مشروعك): لا تنشره ولا تضعه في
   المودع ولا ترسله في المحادثة. سيبقى في أسرار سوبابيز وحدها.

## المرحلة ج — نسخ الملفين كنصّين (أصعب خطوة من الجوال)

الأسهل لو توفّر حاسوب لأي خمس دقائق: افتح الملف بأي محرّر نصوص → تحديد الكل → نسخ.

**ومن الجوال:**
- افتح تطبيق **الملفات / Files** → **Downloads** → اضغط مطوّلاً على
  `google-services.json` → **فتح بواسطة / Open with** → اختر محرّر نصوص
  (مثل *Text Editor* أو *QuickEdit*) → **Select all → Copy**.
- كرّر الأمر نفسه مع ملف حساب الخدمة عند الحاجة إليه.

> 💡 **طريق أقصر لملف google-services فقط:** أرسل الملف **إليّ هنا في المحادثة**
> وأضعه أنا في المودع (هو **ليس سرّاً** — مُعرّف هوية فقط). أما مفتاح الخدمة
> فلا ترسله لأحد — يُوضع مباشرة في GitHub/سوبابيز.

## المرحلة د — ثلاثة أسرار في GitHub (٥ دقائق)

من متصفح الجوال: `github.com/mohamadelfrgena-ai/ps` → **Settings** →
**Secrets and variables** → **Actions** → **New repository secret**:

| اسم السرّ | القيمة |
|---|---|
| `ADDONSTATION_GOOGLE_SERVICES_JSON` | نصّ ملف **google-services.json** كاملاً |
| `ADDONSTATION_FCM_SERVICE_ACCOUNT` | نصّ ملف **حساب الخدمة** كاملاً |
| `SUPABASE_ACCESS_TOKEN` | من <https://supabase.com/dashboard/account/tokens> → **Generate new token** → اسمه `arena-push` → انسخه (يظهر مرة واحدة) |

> السرّان `ADDONSTATION_SUPABASE_URL` و`ADDONSTATION_SUPABASE_SECRET_KEY`
> موجودان عندك من قبل — لا تلمسهما.

## المرحلة هـ — سير واحد يفعل كل شيء على الخادم (دقيقتان)

**Actions** → **Push doctor** → **Run workflow** → اجعل الخيارين `true`:

- `deploy_function` ✔ ⇒ ينشر دالة الإرسال ويرفع مفتاح FCM إلى أسرارها.
- `enable` ✔ ⇒ ينفّذ `35_push_live.sql` ويشغّل الطابور (كل دقيقة + الفوري).

بعد دقيقة، اقرأ **الملخّص في نفس صفحة التشغيل**: تقرير عربي كامل. المتوقّع:

- كل البنود **✓** ما عدا «أجهزة مسجّلة» (سيخضرّ بعد بناء النسخة الجديدة وتثبيتها).
- سيطبع لك **سرّ تشغيل** (`ADDONSTATION_PUSH_CRON_SECRET`) — يمكنك إضافته كسرّ
  للمودع ليُضبط تلقائياً في المرات القادمة.

> إن تعذّر شيء، السير لا يفشل صامتاً: يطبع تحذيراً بالعربية يقول ما بقي
> (مثلاً: انسخ `35_push_live.sql` في SQL Editor واضغط Run).

## المرحلة و — بناء النسخة التي تحمل Firebase (عندما تقول «ابنِ»)

- **لا أبني شيئاً حتى تقول «ابْنِ»** (قيدك الذي وضعته، وما زال قائماً).
- بعد البناء: ثبّت النسخة الجديدة → افتح التطبيق → ستظهر بطاقة
  **«فعّل الإشعارات»** → **فعّلها الآن**.
- من الإعدادات: **«جرّب الإشعار الآن»** ⇒ هذه المرة يمرّ بالمسار الحقيقي
  (قاعدة → طابور → دالة → FCM → جهازك).
- وللتأكد النهائي: اطلب من صديق أن يذكرك `@` في غرفة ⇒ الإشعار يصل في ثوانٍ،
  وكذلك مع التطبيق مغلق.

## جدول الأعطال (اقرأه وقت الحاجة)

| ما تراه | المعنى | الحل |
|---|---|---|
| التطبيق: لافتة **«غير مُهيّأة»** | النسخة المثبّتة بُنيت بلا `google-services.json` | بناء نسخة جديدة بعد إضافة السرّ |
| زر التجربة يقول **no_device** | لا يوجد توكن مسجّل لهذا الحساب | تأكّد أنك مسجّل دخول وأن الإذن ممنوح، ثم افتح التطبيق من جديد |
| الطبيب: **401 unauthorized** | السرّ في القاعدة لا يطابق `PUSH_CRON_SECRET` في أسرار الدالة | أعد تشغيل `push_live_enable` بنفس السرّ |
| الطبيب: **missing_secrets** | الدالة تعمل لكن أسرارها ناقصة | أضف `FCM_SERVICE_ACCOUNT` (وشغّل `deploy_function`) |
| الطبيب: **bad_service_account** | مفتاح حساب الخدمة ناقص/تالف (نسخ ناقص غالباً) | أعد توليده من Firebase وحدّث السرّ |
| الطبيب: **pg_cron مفقودة** | لم تُفعَّل الإضافة | Supabase → Database → Extensions → `pg_cron` و `pg_net` ثم أعد تشغيل السير بخيار `enable` |
| الطابور يزيد ولا يُرسل | لا مهمة مجدولة أو السرّ مختلف | `select * from public.push_doctor();` ثم اتبع السطر الأحمر |

## أوامر للطوارئ (SQL Editor — نسخ ولصق)

```sql
-- أين الانقطاع؟
select * from public.push_doctor();

-- إعادة التشغيل بأمان (نفس الرابط ونفس السرّ)
select public.push_live_enable('https://<ref>.supabase.co/functions/v1/send-push', 'نفس-السرّ');

-- إيقاف الإرسال مؤقتاً
select public.push_live_disable();

-- ما في الطابور الآن؟
select status, category, count(*) from public.push_queue group by 1,2 order by 1,2;
```

## وبعد ذلك — لا شيء آخر

لا جدولة خارجية، ولا خدمة مدفوعة، ولا سيرفر يعمل عندك. كل شيء داخل سوبابيز
(القاعدة + الدالة + الجدولة)، والتطبيق يحمل مفتاحاً عاماً فقط.
